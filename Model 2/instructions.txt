MODEL 2 — LEARNED VISUAL REPRESENTATION
================================================================================

WHAT THIS MODEL REPRESENTS
--------------------------------------------------------------------------------
Model 2 asks whether a *learned* visual representation extracts more grain-size
information from the preprocessed photographs than Model 1's hand-built tile features.

It is the change of KIND that Model 1's promotion test required: Model 1 varied the
feature set fed to a fixed head; Model 2 replaces the feature-producing stage itself.
Everything downstream of the per-tile feature vector stays exactly as Model 1 left it.

WHAT MODEL 1 ESTABLISHED, AND WHY IT CLOSED
--------------------------------------------------------------------------------
Model 1 ran four experiments and the IN-DOMAIN number never moved:

  E1  in-domain LOGO-CV 35.98   Kaggle 172.70
  E2  in-domain LOGO-CV 42.66   Kaggle  71.27
  E3  in-domain LOGO-CV 41.15   Kaggle  61.24   <- best
  E4  in-domain LOGO-CV 39.46   Kaggle  77.12   (probe: colour removed)

Every external gain came from REMOVING features and adding regularisation. That is
variance reduction, not better signal extraction. Against a rank-3 curve representation
ceiling of 7.35, roughly 34 EMD of in-domain headroom is untouched, and E3 (which feature
families carry signal) plus E4 (which colour representation carries it) both indicate that
re-summarising the same hand-built tile features cannot reach it.

THE MAIN COMPARISON — THIS IS THE WHOLE MODEL
--------------------------------------------------------------------------------
      Model 1 E3 hand-built features  ->  ridge
  vs
      frozen DINOv2 ViT-S/14 features ->  ridge

One variable: the per-tile feature vector. Nothing else.

FROZEN ACROSS EVERY MODEL 2 EXPERIMENT
--------------------------------------------------------------------------------
  tiles         the existing 256 px materialised tiles (56.23 mm square at the canonical
                4.5525 px/mm). No new tile size, no new stride, no re-tiling.
  aggregation   two-stage median, tile -> image -> soil, exactly Model 1's code path.
                Low-soil-fraction tiles excluded at soil_fraction >= 0.50.
  head          StandardScaler on features, rank-3 PCA curve basis, closed-form multi-
                output ridge on the curve coefficients.
  output        mean curve + 3 coefficients, then clip to [0,100], cummax, force 100 at
                200 mm. The monotone projection is load-bearing and unchanged.
  metric        trapezoid EMD on log10 d, mean over soils, 0-500 scale. Reconciled against
                the host's published trivial baseline 100.31; the page's printed
                left-endpoint formula gives 102.02 and is NOT what the grader computes.
  validation    leave-one-family-out over the 16 curve-distance families, copied
                byte-identical from E1/E2/E3. No random image-level split. The soil is
                the unit of supervision.
  leakage       scaler and curve basis refit inside each training fold only.
  preprocessing never re-run. config_hash 010f44c36c74 pinned and asserted.

EXPLICITLY OUT OF SCOPE FOR MODEL 2 EXPERIMENT 1
--------------------------------------------------------------------------------
These are not forbidden forever; they are excluded so that E1's result means one thing.
Introducing any of them turns a clean comparison into an unattributable one.

  - fine-tuning or partial fine-tuning of any backbone
  - attention pooling, learned pooling, or multiple-instance pooling
  - new tile sizes, new tile strides, or any change to tiling
  - ConvNeXt, CLIP, ResNet, or any backbone other than the one arm definition
  - different regression heads, or any change to the ridge / curve-basis stage
  - any change to preprocessing, resampling, colour handling, masking or cropping
  - direct 11-output regression or a differentiable-EMD loss
  - ensembles, stacking, or multi-model averaging

If one of these looks necessary mid-experiment, STOP and record why rather than folding it
in. Each is a candidate for a later, separately named experiment.

PRIMARY SELECTION METRIC — AND WHY IT IS NOT THE DEMOTED RULER
--------------------------------------------------------------------------------
Model 1's E1 experiment proved that in-domain LOGO-CV ranks configurations in the WRONG
ORDER for cross-camera transfer, and E4 proved the replacement CAM+RES ruler mis-ranks
even within Model 1 once a representational family is removed. Both rulings stand.

Model 2 E1 nevertheless uses in-domain LOGO-CV as its primary metric, and this is a
deliberate, argued exception rather than a regression:

  E1's claim is narrow: LOGO-CV is invalid for predicting the LEADERBOARD under camera
  shift. It is not a claim that LOGO-CV fails to measure how much curve signal a
  representation carries on devices already seen. That is the representation question,
  and it is the only quantity that was constant across all four Model 1 experiments.

  Therefore: in-domain LOGO-CV may DECIDE Model 2 E1. It may not forecast a Kaggle score.
  CAM+RES is reported for every arm as a diagnostic and as a further calibration point,
  and is never used to select.

This keeps E1 decidable without spending a submission, which matters because the
experiment is designed to be refutable cheaply.

THE CAPACITY CONTROL
--------------------------------------------------------------------------------
A frozen DINOv2 vector is 384-dimensional; Model 1's feature vector is 12. If DINOv2 wins,
the obvious confound is dimensionality rather than pretraining.

Every Model 2 experiment therefore reports three configurations, not two:

  M1   Model 1 E3's 12 hand-built features          the control
  R    the same ViT-S/14 architecture, RANDOM untrained weights   the capacity control
  D    the same architecture, PRETRAINED DINOv2 weights           the claim

R has the same dimensionality, the same receptive field, the same aggregation and the same
head. **An experiment in this model is not interpretable unless all three are present**,
and the notebook refuses to evaluate its own decision gate when any is missing.

EXPERIMENT OUTCOMES SO FAR - E1 AND E2 BOTH REFUTED
--------------------------------------------------------------------------------
E1  TESTED: do 384 frozen DINOv2 tile embeddings beat the 12 hand features under the
    identical head and CV.  REFUTED.  In-domain LOGO-CV: D 44.33 vs M1 43.02.
    Established, in addition to the refutation:
      - R (random-init weights, same architecture) scored 39.78 and APPEARED to win. That
        is the capacity trap, not a result: R selected the grid-floor alpha (0.03), had the
        worst cross-camera transfer of any arm (CAM+RES 78.55), and sat at soil_distance
        0.0000. R is the reason E1's arm table cannot be read on in-domain score alone.
      - D is roughly 5x more camera-stable (camera/soil 0.209 vs M1 1.105) and 28x more
        blur-stable (blur/soil 0.029 vs 0.818) and was still LESS accurate. Robustness and
        informativeness are independent. This is E1's durable finding.
      - Declared probe submitted anyway: Submission_Model2_E1.csv scored 60.56167 on the
        public LB, 0.674 EMD better than E3's 61.24 on 3 of 10 soils, i.e. a near tie.
        Recorded as a PROBE, not a gate pass.
    Declared confound: E1 recorded PATCH_MM = 3.0752 mm, omitting the 256 -> 224 resize.

E2  TESTED: does E1's refutation survive correcting that confound and sweeping patch
    magnification eightfold (crop 256/128/64/32 -> patch 3.5145 / 1.7573 / 0.8786 /
    0.4393 mm) for both D and R.  REFUTED.  No submission was produced; the gate failed all
    three clauses.
      - D lost to R at EVERY crop. Best case +0.96 EMD at crop 128; no CI came near
        excluding zero. (256: +4.55, 128: +0.96, 64: +3.14, 32: +6.24.)
      - No trend. Spearman rho = -0.40, p = 0.60 for D, and the opposite sign for R.
      - The 256 -> 32 change was NOT concentrated in the patch-limited fines (fines -0.68,
        mid -2.88, coarse +2.13). A systematic gain in the fines would have meant the crop
        was smuggling label information; it did not.
      - The whole sweep resolves only 2 more of the 24 soils (12 -> 14) while using 1.6% of
        the tile area. The 10 fines are physically unreachable: resolving them needs a
        sub-24 px window upsampled to 224, which contains no grain information.
    WHAT E2'S RUN DOES LICENCE, AND WHAT IT DOES NOT. E2's own regression checks passed -
    crop 256 reproduced E1's M1 mean to 0.0017 EMD and the control matrix matched Model 1
    E3's to 2.8e-14 - so its MACHINERY is valid and reusable. What is refuted is the
    HYPOTHESIS. Nothing in E3 may inherit any belief that magnification helped, and crop
    128 is not carried forward as a preference despite being D's best crop in E2.

THE ONE QUESTION NEITHER EXPERIMENT ASKED
--------------------------------------------------------------------------------
E1 refuted replacement. E2 refuted rescue by scale. Neither tested whether D's 384 columns
carry information the 12 hand features lack - which is the only reading of E1's invariance
finding that leaves it mattering at all. E3 tests exactly that, by concatenation, against a
label-blind permuted embedding block.

E3  TESTED: complementarity. Fusing the 12 hand features with the 384-dim DINOv2 embedding
    (396 columns, same frozen ridge head, same CV, crop 256) against the hand features alone,
    gated on beating M1, beating a row-permuted noise block, and beating D alone.  REFUTED.
    Ran locally 2026-09-29, CPU only, no Kaggle session. No submission was produced.
      - FUSE@256 43.43 against M1 43.02: fusion is 0.41 EMD WORSE, paired CI
        [-6.69, +7.46], 11 of 24 soils improved. G1 FAILED.
      - SHUF@256 (12 + row-permuted D block) 52.93, i.e. 9.90 EMD worse than M1: the
        instrument is healthy and the permutation control behaved as predicted. P2 CONFIRMED.
        G2 also failed: FUSE - SHUF -9.50, CI [-23.56, +4.82], not significant.
      - Sensitivity crops fuse@c128 43.65, @64 44.01, @32 44.76 - all worse than M1, so no
        magnification rescues fusion either. P7 CONFIRMED.
      - The most instructive number: FR@256 (hand + RANDOM-INIT ViT block) scores 39.26, the
        best in-domain result in the whole experiment, while its CAM+RES is 83.94 - the worst
        transfer of any fused arm. E1's capacity trap reproduced in fused form: in-domain CV
        rewards untrained random projections more than pretrained features. P6 REFUTED in the
        direction that hurts the hypothesis - the random block helped, the pretrained block did
        not.
      - Fusion kept D's ABSOLUTE camera shift (0.64 vs D's 0.62, M1's 1.21) but its
        camera/soil RATIO, 1.1044, is indistinguishable from M1's 1.1048. E1's invariance
        finding does not transfer into the fused model in the units that affect ranking.
      - Gate: G1 FAIL, G2 FAIL, G3 PASS, PROVISO PASS (alpha 300 interior), VALID PASS,
        COMPLETE PASS -> verdict REFUTED, submit False.
      - Integrity note, disclosed in Experiment3.txt section 12b: two defects in the gate code
        were found from run 1's own output (VALID coded with an inverted sign; the FUSE-SHUF
        contrast bound to None). Both were corrected to match the clause text frozen in this
        file BEFORE the run. No clause, threshold or comparator changed, and the verdict is
        identical under both versions of the code because G1 fails either way.
      - 15 of 35 code cells were imported byte-for-byte from E2's notebook, so "the head, CV
        and metric are unchanged" is a fact about the text rather than a claim. All three base
        arms reproduced E2's per-soil vectors within 0.05 EMD, and the emitted data files are
        byte-identical across repeated runs.

MODEL 2 IS CLOSED AT THREE EXPERIMENTS
--------------------------------------------------------------------------------
Replacement (E1), magnification (E2) and complementarity (E3) are the three ways a frozen
backbone could help this target, and all three are refuted. Per the closure rule written into
model_plan_m2e3.md section 17 before E3 ran, no E4 is scheduled. Remaining budget goes to the
Model 1 line, which produced every real gain on the leaderboard.

PROMOTION TEST
--------------------------------------------------------------------------------
  Model 3  a changed output parameterisation or a changed task framing
  Model 4  changed aggregation / pooling as its own subject
  Model 5  explicit domain adaptation as its own subject

A change of backbone WITHIN the frozen-head protocol is a new EXPERIMENT in Model 2, not a
new Model. A change to what the model OUTPUTS, or to how tiles are POOLED, is a new Model.

RULES
--------------------------------------------------------------------------------
